ALi M1543C South-Bridge Interface

The Acer Labs (ALi) M1543C is the PCI-to-ISA south bridge of the AlphaServer ES40 and ES45 -- the counterpart to the Cypress CY82C693 used by the DS10/DS20. EmulatR models it so that ES40 firmware enumeration finds the bridge instead of master-aborting. ES40 is Tsunami (21272) silicon, so the south bridge is the only platform piece that differs from the DS10.

Function 0 advertises header type 0x80 (multifunction). The bridge/interrupt-routing config registers the ES40 SRM programs live at config index 0x40-0x4B: ISA-bus / decode / IDE control (0x40-0x47) and PCI INTx (PIRQ) steering to ISA IRQs (0x48-0x4B).

 

EmulatR model

chipsetLib/AliM1543C.h mirrors the Cypress contract exactly: it implements IPciDeviceHandler + IIoPortHandler over a 256-byte config space, with read-only-protected vendor/device IDs and store-through config writes. A small AliPciFunctionStub gives the SRM's multifunction probe valid headers for the IDE/USB/PMU companions instead of a master abort. The header was ported from Processor Support/ALi M1543_Datasheet (Section 4) and verified standalone with g++ (identity reads back 0x1533_10B9; PIRQ store-through and RO protection both correct).

 

Selection and wiring

TsunamiChipset::wireDevices() selects the bridge from the m_southBridge enum (the former isAliPlatform(model) string test was retired) -- ES40/ES45/DS25 wire the ALi (m_ali), everything else wires the Cypress (default). The SAME lever also selects the func1 IDE (ALi M5229 vs Cypress), so bridge and IDE stay consistent. DS10 still resolves to Tsunami / cpuCount 1, byte-identical to before, so the working path is untouched.

 

Faithful vs stubbed

Faithful: func0 identity, class, multifunction header, companion identities, config store-through with RO IDs, the model-gated selection, and -- since Phase 2B -- the func1 M5229 IDE via AliM5229Ide (selected by the same south-bridge lever; it answers the taskfile / IDENTIFY probe on dqa0 / dqb0). Stubbed (TODO ali-irq-route): the PIRQ steering (idx 0x48-0x4B) and IDE INTAJ level/edge (0x44) currently store through with no field effect; the USB (M5237) and PMU/SMBus (M7101) companion internals are not modeled beyond their identities.

 

Run the ES40 with [System] model=ES40, cpuCount=1 and [ROM] firmwareImage=firmware/es40_v7_3.exe. Build and smoke-test the DS10 first to confirm no regression. The most likely first divergence is ALi config/IRQ-routing init (only the identity is faithful so far), ahead of the halt-button check. Full detail: journal 20260617_es40_ali_m1543c_interface.md.
