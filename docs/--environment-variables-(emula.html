Environment Variables

The runtime environment variables EmulatR reads at launch, plus the compile-time flags that look like env vars but are CMake options. All values are read with std::getenv -- set them in the launching shell before starting the process (inline bash assignment is the normal form).

 

Three gotchas

- Presence, not value. Most gates test only that the variable is set, so VAR=0 still ENABLES them. Exceptions that parse a value are noted below.

- Read once. The trace / diagnostic gates cache their result on first call; exporting them mid-run has no effect.

- Paths are CWD-relative. The stop sentinel and the snapshots directory resolve against the launch directory; launch from the Emulatr root.

 

Snapshot / autoload

Variable

Default

Effect

EMULATR_CONSOLE_SNAPSHOT

off

Arms the console-marker snapshot watch; a matching input line writes a .axpsnap.

 

EMULATR_CONSOLE_SNAPSHOT=1 arms a console marker watch. The marker (default, overridable via EMULATR_SNAPSHOT_MARKER) is the literal line:

 

>>>set oem_string snapshot

 

EMULATR_SNAPSHOT_MARKER

set oem_string snapshot

The exact line that triggers a console snapshot (internal whitespace NOT normalized).

EMULATR_AUTOSNAP

on

=off disables periodic auto saves. Mirrors --autosnapshot off.

EMULATR_NO_AUTOLOAD

unset

Skip autoload-newest; force a genuine cold boot. Mirrors --no-autoload.

EMULATR_SNAPSHOT_PRUNE

unset

Enable pruning of old snapshots (off by default).

 

Process / platform

Variable

Default

Effect

EMULATR_STOP_FILE

EMULATR_STOP

Path of the graceful-stop sentinel; touch it to flush flash NVRAM and exit cleanly.

EMULATR_NO_PUTTY

unset

Do not auto-launch PuTTY; the listen socket still comes up.

EMULATR_CONSOLE_PORT

10023

TCP console port (PuTTY auto-launch follows it). Give each instance its own port.

EMULATR_FLASH_ROM

<firmware>.rom

Backing file for the flash / NVRAM image. Isolate it per instance to avoid corruption. When unset the backing is DERIVED from the firmware image name (es40_v7_3.exe -> es40_v7_3.rom in the same directory); the fixed ds10_flash.rom is only the legacy final fallback. Resolution order: EMULATR_FLASH_ROM > ini [ROM]flashImage > <firmware>.rom > ds10_flash.rom.

example bash: EMULATR_CONSOLE_SNAPSHOT=1 EMULATR_FLASH_ROM=ds20_flash.rom ./run_fw.sh ds20 cold 2>&1 | tee ds20_pastdva0_$(date +%H%M%S).out

 

Adding EMULATR_FLASH_ROM=ds20_flash.rom configures DS20 with the persisted NVRAM ROM image (serial + memory_test none).

 

No --max-cycles --  (cold default - cycles count are unlimited).

Build clean (PROBES off) first if you can -- the marker feature works on any build, but it kills the DIVERT-REI spam and gives a production-grade snapshot.

EMULATR_PLATFORM_CONFIG

derived DS10

Override the platform manifest.

EMULATR_DIAG_PCHI

High bound of the retire-diagnostic PC window (value = hex PC).

EMULATR_DIAG_CYCLO

Low bound of the retire-diagnostic cycle window (value).

EMULATR_DIAG_CYCHI

High bound of the retire-diagnostic cycle window (value).

EMULATR_DIAG_WREG

Register the retire diagnostic watches (value).

EMULATR_DIAG_WMIN

Minimum value threshold for the retire diagnostic (value).

EMULATR_DIAG_CAP

Cap on retire-diagnostic output lines (default 200).

EMULATR_DTBMISS_DIAG

Enable the DTB-miss diagnostic.

EMULATR_VACTL_DIAG

Log every VA_CTL and I_CTL write (the VACTL-DIAG probe).

EMULATR_VPTB_DIAG

Diagnostic for MTPR_VPTB / VPTB writes.

EMULATR_PTBR_DIAG

Diagnostic for the PT__PTBR page-table base.

EMULATR_IIC_DIAG

PAL-level IIC diagnostic.

EMULATR_BOOTTRACE

Enable the pipeline boot trace.

EMULATR_2D_NOOP

Treat the CALL_PAL 0x2d leaf as a no-op instead of the labeled fault scaffold (bring-up gate).

EMULATR_CSERVE_START_MODE

Selects how the B+ handoff is taken at CSERVE START (0x42). Default guest (Option A) mirrors AXPBox vmspal_call_cserve exactly -- it sets p23 to the CALL_PAL return PC and diverts to the guest cfw_start/exit_console, letting the real PAL do the mode/VPTB/IPL transition. Set cpp for the old C++ B+ replica.

EMULATR_CSERVE_AUDIT

When set (=1), the CSERVE default case captures the missing contract for every func EmulatR still stubs, emitting CSERVE-CONTRACT-MISSING: func=0x.. R16/R17/R18/R0 callerPc=.. (one record per distinct func) so each unhandled func can be cross-referenced to its guest cfw_* handler. Set empty to disable.

EMULATR_CSERVE_ROUTE

When set (=1), the CSERVE default case DIVERTs to the guest sys__cserve dispatcher (mirror-AXPBox p23 + divert, R16 intact) instead of no-op'ing. Closes 0x65 MP_WORK_REQUEST (the MP$RESTART boot post): guest cfw_mp_work_request saves R18 to CNS__WORK_REQUEST so the console proceeds past the re-init loop. Faithful for every func (unknown codes hit the guest's own hw_ret(p23) no-op). Emits CSERVE-ROUTE lines. Set empty to disable.

EMULATR_DTBM_PROBE

Enable the DTB-miss probe (silent and zero-cost when unset).

EMULATR_HALT_DIAG

Pin where the console halts on the b dqa0 handoff: the swppal / console_exit transfer PC and halt code.

EMULATR_IFETCH_DIAG

I-fetch diagnostic at the missing OS-side base: dumps i_ctl / va_ctl VPTB, ptbr, and palBase at that point (capped).

Probe / experimental

EMULATR_IDLEWARP fast-forwards the idle loop to the next timer tick (clean). EMULATR_GCT_WATCH, EMULATR_BREAK_ON_PA10, EMULATR_CHECKPOINTS, and EMULATR_GATE are pinpoint debug gates. Note: EMULATR_RSCCWARP is QUARANTINED (caused boot corruption) and EMULATR_TICKWARP is a deprecated no-op. The ES40 bring-up probes EMULATR_TIG_RESET (model the TIG module reset), EMULATR_UDELAYWARP (warp the 0x6a514 micro-delay loop), and the trace gates EMULATR_TIG_TRACE / EMULATR_RSCC_DIAG are gated behind the compile-time EMULATR_BRINGUP_PROBES and are experimental / provisional. EMULATR_UDELAYWARP_LEGACY_UNSAFE is the legacy micro-delay warp at PC 0x6a514, superseded by EMULATR_UDELAYWARP and marked UNSAFE -- do not re-enable.

 

Compile-time flags (NOT runtime env vars)

These are CMake options baked in at build time -- setting them in the shell does nothing: EMULATR_MEMDIAG (per-instruction logging, ~900x slowdown, keep OFF), EMULATR_DIAGNOSTIC_LOGGING (non-Release per-subsystem logging), and the EMULATR_LOG_* spdlog level macros.

 

CLI flags that mirror env vars

--autosnapshot off = EMULATR_AUTOSNAP=off; --no-autoload = EMULATR_NO_AUTOLOAD=1. --max-cycles, --snapshot-on-pc, and --snapshot-name-tag have no env equivalent.
