South Bridge

The south bridge is the PCI-to-ISA bridge that carries the legacy I/O plane of an Alpha system: the 8259A interrupt-controller pair, the 8254 timers, the MC146818 real-time clock / CMOS, the 16550 UARTs (COM1/COM2), the 8042 keyboard controller, an IDE controller, and the Super I/O (floppy, parallel). It sits on PCI hose 0 and is one of the first devices the SRM console enumerates.

 

The south bridge is chosen by platform and is independent of the core-logic chipset generation. EmulatR models two:

The device-attachment contract

Both bridges implement the same two interfaces from chipsetLib/IDeviceHandlers.h, so the chipset wires them identically:

 

•IPciDeviceHandler -- pciConfigRead/Write(reg, value, width) over a 256-byte PCI configuration space. This is how the SRM finds the bridge during slot enumeration.

•IIoPortHandler -- ioRead/Write(port, value, width) for the legacy ISA I/O window.

 

Model-gated selection

EmulatR picks the bridge in TsunamiChipset::wireDevices() from a SouthBridge enum (m_southBridge; the former isAliPlatform(model) string test was retired) -- ES40 / ES45 / DS25 wire the ALi, everything else wires the Cypress (the default). The SAME lever also selects the IDE controller (func 1) -- ALi M5229 or Cypress -- so bridge and IDE stay consistent by construction. The model string reaches the chipset because Machine constructs it from the ini [System] model. The ISA devices behind the bridge live at fixed ports (8259 at 0x20/0xA0, RTC at 0x70, COM1 at 0x3F8, ...) and are registered separately, so they are reused unchanged regardless of which bridge is selected.

 

Only the bridge identity and config space differ between the two. The SRM probes the bridge's vendor/device ID and then programs bridge-specific control and interrupt-routing registers; getting those config-space responses right is what keeps enumeration from stalling.
