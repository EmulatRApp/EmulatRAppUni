EmulatR - Known Gaps

Release checkpoint = DS10 + DS20 + ES40 certified to the same boot milestone. DS10/DS20 reach their SRM prompts reliably (~200 iters); ES40 reaches P00>>> but does not yet complete init. Delete a row when its gap is closed. IDs are stable handles (a closed row's ID is not reused).

 

Severity legend. BLOCKER: on the ES40 boot/console path, gates the checkpoint. OPEN: unresolved contradiction to reconcile. GAP: fidelity or downstream, not blocking the prompt. REF: blocked on an absent primary source. DEFER: intentional deferral (silicon-mode / V5 / post-prompt). PROV: a value is _PROVISIONAL.

G-07

OPEN

Exec mode

DS20 enumerates IDE under the ISP default even though the ISP gate is upstream of the Cypress special case; unreconciled against the ds20 (pc264) binary.

Trust in the ISP model

G-08

DEFER

Exec mode

Silicon-mode delays busy-wait on RSCC; krn$_micro_delay returns immediately only in ISP mode, so silicon grinds. EmulatR models RSCC = cycleCount/5594; safe warp advances cpu.cycleCount coherently so RSCC crosses limit and the spin exits (as EMULATR_IDLEWARP does). Do NOT re-enable the quarantined EMULATR_RSCCWARP (jumped ticks, rewrote 0x3c970 out-of-band = confirmed boot corruption). Gated EMULATR_PLATFORM=silicon, discuss-before-code.

 

Silicon mode is now a live surface for the warp validation.

Silicon-mode completion

REF

OS boot

Milestone

G-23

BLOCKER

Boot

RUN/STOP handling on the boot path; mechanism _PROVISIONAL - CPU RUN/STOP (console halt/continue, HWRPB BIP/RC handoff) and/or device RUN/STOP (controller start/stop bit in the boot driver). Future blocker once boot is wired; trace to pin the mechanism before scoping.

boot handoff (G-03)

G-24

OPEN

Silicon

ES40 does not yet initialize in silicon mode (EMULATR_PLATFORM=silicon) -- outstanding diagnostic, active surface (not a deferral). Under warp the RSCC micro-delay spin now exits (G-08), but ES40 init still does not complete on the silicon path; entangled with the ISP-path init blockers (G-02 / G-10) and the exec-mode reconciliation (G-06 / G-07). Needs an evidence-first trace of where silicon-mode init diverges before scoping a fix.

ES40 silicon-mode bring-up

G-25

DEFER

Config/CLI

Unified configuration precedence not yet implemented. TODAY: built-in defaults < EmulatrV4.ini < CLI (CLI wins) for shared tunables (firmware, memory). EMULATR_* env vars are ORTHOGONAL -- most are ENV-only diagnostic/trace toggles; the two that overlap a CLI flag (--no-autoload / EMULATR_NO_AUTOLOAD, --autosnapshot / EMULATR_AUTOSNAP) are OR/AND-merged, not ranked. INTENDED: a single order ini < CLI < ENV (ENV overrides both), by threading env reads through the same settings resolver as ini/CLI.

Unified config override (intended)

G-26

DEFER

Config/INI

Default settings file is the versioned EmulatrV4.ini; INTENDED name is EmulatR.ini (release versioning handled by the directory tree / hive, not the filename). Rename spans the loader search paths (IniLoader::defaultSearchPaths), the shipped config/EmulatrV4.ini, the tools/ scripts that reference it, and six doc topics. Keep EmulatrV4.ini as a back-compat fallback in the search order during the transition.

Filename cleanup (intended)

 

Notes

Release-critical set (must clear for the DS10/DS20/ES40 checkpoint): G-01, G-02, G-03, G-04, G-10, plus the G-07 reconciliation. All other rows are fidelity, reference-blocked, or Phase-B/V5.

 

Next probe (evidence-before-scope): a compile-gated NXM-address probe at the raise site to confirm or refute G-10 before any Pchip-decode edit lands.

 

Unifying failure mode across G-05/G-10/G-14/G-20: an unmodeled region returning a plausible-looking value (0x00 or 0xFFFF...) the firmware branches on, so the symptom surfaces far downstream from the defect. Every CSR the console reads must be decoded and faithful; INERT-TRUTHFUL store-through is allowed only where no consumer reads a side-effect.
