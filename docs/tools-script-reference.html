Tools Script Reference

A consolidated inventory of every shell (*.sh) and Python (*.py) script in the EmulatR source tools/ directory. This is the reader-facing companion to the on-record manifest HMDocs/Maps/file_index.md; both are regenerated from the same source tree.

 

How the scripts are deployed

On every build, the CMake POST_BUILD step (root CMakeLists.txt) stages the tool scripts into the run directory (out/build/<config>/) using a file(GLOB ... CONFIGURE_DEPENDS) over tools/*.sh and tools/*.py, so a newly added top-level script deploys automatically. Two rules apply:

•run_fw.sh is special: it is staged to the run-dir ROOT (beside Emulatr.exe) because it anchors to its own directory and launches the binary directly.

•Every other top-level script is staged to <run-dir>/tools/ and locates config/, firmware/, and the manifests as siblings of the run-dir root. The tools/host_decompressor/ and tools/ghidra_scripts/ subtrees are NOT runtime tools and are deliberately excluded.

All shell scripts target Git Bash / MSYS2 on Windows (the supported PC host). Each carries a uniform platform guard that detects the host via uname -s and prefers Emulatr.exe, falling back to a bare Emulatr for a macOS/Linux build; sibling scripts are invoked through bash so they do not depend on the executable bit (which an NTFS checkout drops). The two host-aware SRM launchers (run_srm_trace_full.sh, run_es40_srm_trace_full.sh) and vsenv.sh already branch for macOS. Python utilities require a Python 3 interpreter on the host.

 

Firmware launch & SRM boot

Script

Purpose

run_fw.sh

Launch one v7_3 firmware image with 4 GiB RAM for a chosen model (ds10/ds20/ds25/es40/es45); cold or warm boot. Staged to the run-dir root.

run_srm_trace_full.sh

Host-aware, model-parameterized SRM cold-boot with a full comprehensive trace. The general launcher the per-model wrappers delegate to.

run_es40_srm_trace_full.sh

ES40 (Clipper) SRM cold boot with the full comprehensive trace.

run_ds10_trace.sh

Thin wrapper: DS10 comprehensive SRM trace (delegates to run_srm_trace_full.sh).

run_ds20_trace.sh

Thin wrapper: DS20 comprehensive SRM trace.

run_es40_trace.sh

Thin wrapper: ES40 comprehensive SRM trace.

run_ds20_showdev.sh

Cold-boot DS20 to P00>>> with a PuTTY console attached so "show dev" confirms both dqa0 (disk) and dqa1 (CD) on the CY82C693 IDE.

run_es40_showdev.sh

Cold-boot ES40 to P00>>> with PuTTY and the IDE config-space trace, to diagnose ES40 device enumeration.

run_ds20_ide_trace.sh

Cold-boot DS20 with the IDE probe/command trace on (retire trace off); boots to P00>>> for show dev / boot dqa0/dqa1.

run_ds20_putty.sh

Cold-boot DS20 with an attached PuTTY console so the cosmetic MHz badge rewrite is visible live and in the log.

run_ds20_bplus.sh

DS20 cold boot with the B+ primary-bootstrap restart stack enabled; a thin wrapper that arms the CSERVE handoff knobs and delegates to run_ds20_showdev.sh.

run_ds20_optfw_trace.sh

Capture the DS20 option-firmware to LFU decision with the DIAG retire facility; a thin wrapper that arms the cycle window and delegates to run_ds20_showdev.sh.

run_es40_hookb.sh

Run the ES40 boot from the CLI build and pull the ACVPROBE HOOKB PTE-verdict lines (valid/kre/pfn).

run_es40_rscc_ab_warp.sh

ES40 RSCC A/B, Case A (warp ON): reproduce the LFU "Initializing...." hang with idle-tick warp enabled; delegates to run_es40_showdev.sh.

run_es40_rscc_ab_nowarp.sh

ES40 RSCC A/B, Case B (warp OFF): the faithful-timing control run; delegates to run_es40_showdev.sh.

run_initloop_trace.sh

Capture the ES40 "Initializing...." stuck-loop body (0x12c270) with the retire-trace facility; delegates to run_es40_showdev.sh.

launch_vms_boot.sh

Cold-boot DS10/EV6 and boot OpenVMS Alpha V8.2 from dqa1.

Turnkey RelWithDebInfo build of Emulatr.exe for the ES40 target.

build_test_run.sh

Trace analysis & firmware utilities (Python + Ghidra)

Script

Purpose

alpha_disasm.py

Minimal Alpha (EV6) disassembler for reading PAL and console code by file offset.

analyze_retire_trace.py

Find the dominant PC loop (the wedge body) in a retire-compact trace.

diff_traces.py

Normalize and compare two EmulatR trace logs.

mkdisk.py

Generate a raw, stamped, writable disk image for the dqa install target.

profile_resolve.py

Annotate RetireProfiler dumps with SRM/PAL symbols and region rollups.

snapmap.py

Decode an .axpsnap and hex-map its header, chipset block, and HWRPB.

trace_reg_backtrace.py

Data-flow backtrace of a register through an EmulatR trace.

decompile_ds10.sh

Dump C source from an already-analyzed Ghidra project (headless, decompile-only).

 

Environment setup (source, do not execute)

Script

Purpose

env.sh

Put the VS2022-bundled CMake + Ninja (and Qt / MSVC toolchain) on PATH for Git Bash command-line builds. Source it: source tools/env.sh.

vsenv.sh

Cross-platform sibling of env.sh: uname-gated MSVC import on Windows, no-op-with-warning on macOS/Linux.

 

Packaging / release

Script

Purpose

make_redist.sh

Package a built run directory (out/build/<config>) into a versioned zip under redist/, named after the H&M documentation version. Excludes logs, traces, the licensed firmware/*.exe images, and itself. Usage: ./tools/make_redist.sh [config].

 

Session / Git commit helpers

Script

Purpose

commit_es40_p00.sh

Stage, commit, and push the ES40 "boots to P00>>>" work (guarded).

commit_20260713_tig_reset.sh

Note: the dated commit_*.sh helpers and the developer build/diagnostic scripts are session tooling. They deploy with the run directory but are not needed to operate the emulator; beta testers use the launch scripts above.
