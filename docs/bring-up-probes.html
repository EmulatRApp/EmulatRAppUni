Bring-Up Probes (EMULATR_BRINGUP_PROBES)

Over hardware bring-up, many one-off probe prints were left in the run path -- per-step CPU samplers, memory watchpoints, PAL-transition traces, and end-of-run profiler dumps -- emitted as raw fprintf(stderr) on the hot loop. They are gathered behind a single COMPILE gate, EMULATR_BRINGUP_PROBES, so that when it is off they cost nothing (the code is not compiled at all, not merely skipped at run time). The gate defaults OFF: a normal build emits only initialization messaging, snapshot notices, and genuine error messages.

 

What it looks like when ON

If the probes are compiled in, the console / stderr carries lines such as:

 

PCSAMPLE cyc=67108864 pc=0x60093c pal=0 ra=0x6014bc

[HW_REI XITION #254] pc=0x...600351 REGISTER Rb=23 rawTarget=0x...6009a4 PAL->native excAddr=0x...6009a4 cyc=67293400

 

Seeing these in a build you expected to be quiet -- including a release build -- means the gate is ON (see the cache note below).

 

Enabling and disabling

The gate is a CMake option, toggled at configure time from the repository root, then picked up on the next build:

 

Action

Command (from the repo root)

Enable (debug / relwithdebinfo)

cmake -DEMULATR_BRINGUP_PROBES=ON . && tools/build_emulatr.sh

Disable

cmake -DEMULATR_BRINGUP_PROBES=OFF . && tools/build_emulatr.sh

Check the current cache value

grep EMULATR_BRINGUP_PROBES CMakeCache.txt

 

The cache gotcha

EMULATR_BRINGUP_PROBES is a CACHED CMake option. Its OFF default only applies the FIRST time a build tree is configured; once you have set it (for example -DEMULATR_BRINGUP_PROBES=ON during debugging), that value is remembered in CMakeCache.txt and persists across every subsequent build until you explicitly reconfigure with the opposite value. The build helper tools/build_emulatr.sh does NOT reset it. So if a release build is noisy, the fix is to turn the cached option off and rebuild:

 

cmake -DEMULATR_BRINGUP_PROBES=OFF .

tools/build_emulatr.sh release

 

As a rule, keep the gate OFF for any release or distribution build; enable it only in a debug or relwithdebinfo tree while actively chasing a bring-up issue, and turn it back off when done.
