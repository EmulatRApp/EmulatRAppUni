Release Notes

EmulatR brings the real DEC/Compaq Alpha SRM console firmware to life on emulated Tsunami/Typhoon-class hardware. Each release records what landed, what was fixed, and the current known limitations. Entries are newest first.

 

v1.4.4 (Beta) — 2026-07-23

This beta reaches the SRM >>> prompt on DS10, DS20, and ES40. Guest-operating-system boot is not yet available (see Known limitations below).

 

Highlights this cycle

•A second classic Alpha comes to life. The DS20 now cold-boots to the SRM >>> prompt and badges correctly as AlphaServer DS20 — joining DS10, with ES40 (Clipper) bring-up also reaching the console.

•Platform manifest system. Each model's device tree is described by a runtime-loaded <firmware>_platform.json, editable through the Platform Editor desktop application (editors/platedit_qt) with live validation and format-preserving save.

•Deterministic execution substrate + fast resume. A multi-agent scheduler (agent + dispatcher, Sequential==Threaded verified) and Level-1 snapshots (auto-save / autoload-newest, plus an entry snapshot that skips the firmware decompressor).

•New device models. Floppy FDC, keyboard + VGA console, and IDE/ATAPI storage (Cypress func1 on DS10/DS20; ALi M5229 on ES40) over a common block-media seam.

•Cross-platform. macOS/Linux build hardening alongside the Windows build.

•Packaging & docs. Versioned redistributable packaging, the full user guide shipped inside the package, and this release-notes track.

 

Fixed

•DS20 model badging — root-caused to an IIC completion-interrupt gap and fixed; the console now reports the correct system identity.

•ES40 memtest ACV — resolved (an AAR ASIZ decode-width mismatch); a spurious CSERVE 0x66 get_time behavior was identified as a regression and removed (the 0x66 no-op is the faithful behavior).

•ES40 console — SCB base-mismatch halt fixed and the COM2 console backend landed.

•MMU / TLB — the DTB/ITB are now modeled as truly 128-entry fully-associative, fixing a conflict-eviction thrash.

•Memory — a page-crossing store overrun in the sparse pager was fixed.

•Build portability — added the explicit <new> / <cstdlib> includes that the Release configuration and the clang (macOS) build require.

 

Known limitations (what to expect in this beta)

•No guest OS boot yet. The SRM-to-OS hand-off at VA 0x20000000 is the active frontier: the VMB loads and builds the HWRPB/page tables but the transfer to the OS entry does not yet fire.

•OpenVMS/Tru64 install is gated on floating point. The FP unit is an IEEE-T proof-of-concept; VAX G/F float (which VMS relies on) is not yet implemented.

•Partial PCI enumeration. EmulatR currently enumerates about one on-board device where silicon shows about nine; the full device list and SYSBOOT> path depend on the PCI bus walk still in progress.

•No Ethernet yet. The on-board DE500 / 21143 ("Tulip") NIC is designed but not implemented.

•Single-CPU only. SMP is scaffolded but boots run cpuCount=1 deliberately.

•DS25 / ES45 (Titan chipset) are experimental — model-only, not yet booting.

•Cosmetic mismatches. The clock-MHz banner and a handful of SRM defaults differ from real hardware.

 

Beta test focus

We would most value reports on:

•Cold-boot to >>> on DS10 / DS20 / ES40 (via run_fw.sh or the run_* helper scripts).

•Console over PuTTY/plink on TCP 10023 — show config, show device, show memory, environment variables.

•Storage — attaching a virtual disk / CD-ROM and show dev enumeration.

•The Platform Editor — opening and editing a <model>_platform.json.

Because EmulatR treats itself as the primary correctness oracle, anything that diverges from real-hardware behavior is worth reporting.

 

Getting started

Two build variants are provided: EmulatR_v1.4.4_relwithdebinfo.zip (diagnostic logging and trace facilities compiled in — preferred for beta, since it lets you capture the logs/traces that make a bug report actionable) and EmulatR_v1.4.4_release.zip (optimized, diagnostics compiled out; for performance and clean runs).

Firmware is not included — DEC/Compaq/HPE SRM images are licensed, so supply your own <model>_v7_3.exe in ./firmware/. Full documentation ships in documentation/EmulatRGuide.pdf.

 

Reporting issues

Please include the model, the build variant, the run command, and — on a RelWithDebInfo build — the run log and any .trc from logs/ and traces/.
