run_fw.sh

Launches EmulatR V4 against one v7_3 firmware image with 4 GiB of RAM. Resolves the model variant, sets the [System] model line in config/EmulatrV4.ini for the run (backing up and restoring the ini on exit), copies the firmware into the build-dir firmware/ directory, and launches Emulatr.exe with console and stderr teed to fw_<name>_<ts>.out. Git Bash on Windows; anchors to the script's own directory as the build dir.

 

Usage

./run_fw.sh <ds10|ds20|ds25|es40|es45> [cold] [extra Emulatr args...]

 

Arguments

model (required): one of ds10, ds20, ds25, es40, es45 -- maps to the [System] model written into the ini.

cold (optional 2nd arg): forces a genuine cold boot -- passes --no-autoload and purges stale auto_*.axpsnap (predig_* fast-forward anchors are preserved). Without it the run is warm: autoloads the newest snapshot and keeps writing periodic autosnaps.

 

extra: any further arguments are passed through verbatim to Emulatr.exe (e.g. --max-cycles 0x10000000).

 

Notes

Memory is fixed at 4 GiB. The model is ini-driven; there is no --model flag. The SRM console listens on TCP 10023 -- connect with PuTTY/plink in raw mode to reach the >>> prompt.

 

bash - Examples

 

export EMULATR_FLASH_ROM=ds20_flash.rom

unset EMULATR_IIC_WATCH          # storm's gone; drop the probe noise

cd /d/EmulatR/EmulatRAppUniV4/Emulatr/out/build/release

./run_fw.sh ds20 cold --max-cycles 0x480000000 2>&1 | tee ds20_to_prompt_$(date +%H%M%S).out

# clean-stop sentinel from another shell once you see >>> (flushes flash NVRAM):

#   touch /d/EmulatR/EmulatRAppUniV4/Emulatr/out/build/release/EMULATR_STOP
