Running from a Run Directory

The run directory is the folder that holds the built executable -- out/build/<config>/, where <config> is relwithdebinfo, debug, or release. It is the runtime root: firmware, config, logs, traces, snapshots, the platform manifests, and the deployed helper scripts all live there. The project's tools/ folder is the source of truth for those scripts; every build copies them into the run directory, and you run from that copy.

 

The model

<project>/tools/ is the committed repository of run and diagnostic shell scripts, covering the execution permutations (models ds10 / ds20 / ds25 / es40 / es45, across configs and trace modes). On every build, CMake copies tools/*.sh and tools/*.py into out/build/<config>/tools/. The copy is GLOB-driven with CONFIGURE_DEPENDS, so a newly added script deploys on the next build with no hand-editing. You then run from the run directory's copy:

 

out/build/<config>/tools/<script>.sh

 

Why it runs from anywhere

Every runtime script sources tools/_emulatr_runenv.sh, which locates the run directory from the script's own path (via BASH_SOURCE) -- never a hardcoded or source-tree path. It then cds into the run directory and pre-creates logs/ traces/ snapshots/. Because the emulator also writes relative to its current directory, all output lands under the run directory automatically. The current working directory does not matter -- these are equivalent:

 

cd out/build/relwithdebinfo && ./tools/run_ds10_trace.sh

/any/where $ /full/path/out/build/relwithdebinfo/tools/run_ds10_trace.sh

 

Distributing a build (download, unzip, run)

A distributed artifact is the run directory itself: zip out/build/<config>/ (Emulatr.exe, the Qt DLLs, firmware/, config/, the platform manifests, and tools/). The end user unzips it anywhere, opens tools/, and runs a script -- for example:

 

./tools/run_ds10_trace.sh

 

No source tree is required. The scripts use only run-dir-relative paths; firmware and manifests are the copies already shipped in the run directory.

 

Where output lands

Relative to the run directory (out/build/<config>/):

 

Directory

Contents

logs/

Run and console logs, named purpose_YYYYMMDD_HHMMSS.log.

traces/

Retire / dec / machine listings and .trc traces.

snapshots/

Saved machine states (.axpsnap checkpoints).

firmware/

The v7_3 SRM images the run boots.

config/

EmulatrV4.ini (model set per run, restored on exit).

 

Environment knobs

 

Variable

Effect

RUN_DIR=<dir>

Force the run directory, overriding self-location.

CONFIG=relwithdebinfo|debug|release

Steers only the developer fallback used when a script is run from a source checkout instead of a shipped run directory; ignored once a shipped run directory is found.

 

Adding a new script

1. Drop the .sh in <project>/tools/.

2. Open it so it self-locates the run directory:

 

set -euo pipefail

SELF_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"

source "$SELF_DIR/_emulatr_runenv.sh" # sets RUN_DIR, BIN, HOST; cd's in

 

3. Use only run-dir-relative paths for output (logs/, traces/, ...).

4. Rebuild -- CMake auto-deploys it to out/build/<config>/tools/.
