## 1. Why read the reference

The 0x20000000 halt reproduces reliably on both dqa0 and dqa1 (JRN-VMB-001
Sec 7.6).  H1 (miss never vectored) is ruled out (JRN-VMB-002 E-0).  Step 1b's
elimination proof shows the fetch is an ITB HIT composing PA 0 (PFN 0), and the
miss probe fired ZERO times -- so there was no ITB miss at all.  Before adding
more instrumentation, establish what a CORRECT boot does at 0x20000000, from the
authoritative source rather than from inference.  boot.c is the SRM console
`boot` command; it is the reference for everything that happens past P00>>>.

## 2. The reference boot-beyond-P00>>> flow (apisrm/ref/boot.c)

Observed in code, in order:

  1. Open the boot device, read the boot block, load the secondary bootstrap
     (VMB) into physical memory at `base` = phys_to_virt(base_pfn * PAGESIZE).
     Our run logs `base = 5bc000`, so base_pfn = 0x5bc000 / 0x2000 = 0x2DE
     (8 KiB pages, PAGESIZE = 0x2000).
  2. Build the HWRPB (build_hwrpb) and the per-CPU SLOT / HWPCB.
  3. Build a THREE-level page table (page_table_levels == 3) in memory at
     consecutive PFNs: l0pt / l1pt / l2pt / l3pt0 / l3pt1.  PTBR = l1pt_pfn
     for the 3-level case (pt_pfn).
  4. Map three virtual regions in the L2 table:
       - 0x10000000 (region 1) -> l3pt0  (firmware / HWRPB / PALcode / heap)
       - 0x20000000 (region 2) -> l3pt1  (the SYSTEM SOFTWARE address space)
       - 0x40000000 (region 3) -> l2pt   (self-map)
  5. Fill l3pt1 with the bootstrap image mapping (the money loop):

         for( ptx=i=0, pfn=base_pfn; i < image_pages; i++ ) {
             ((int*)l3pt1)[ptx++] = 0x1101;     // PTE flags: V | KRE | KWE
             ((int*)l3pt1)[ptx++] = pfn++;      // PFN, starting at base_pfn
         }

  6. Set the transfer state:
       - slot->HALT_PC             = 0x20000000 + image_start  (image_start
                                     typically 0 -> transfer PC = 0x20000000)
       - HWPCB.PTBR                = pt_pfn (l1pt_pfn)
       - HWPCB.ASN                 = 0
       - hwrpb->VPTBR              = 0x0000000200000000
                                     (VPTBR[1] = 1 << (13+10+10-32) = 2)
       - write_ipr APR$K_VPTB, APR$K_PTBR, APR$K_KSP
       - write_pc( slot->HALT_PC )
  7. map_via_page_table fixups for HWRPB / dispatch / fixup / env, checksum the
     HWRPB, then hand off.  The actual context swap (load PTBR/ASN, begin
     fetching at 0x20000000 in the new mapping) is PALcode's job (swpctx-class),
     NOT boot.c.

## 3. The exact expected entry for VA 0x20000000

From step 5, l3pt1[0] is the PTE for VA 0x20000000:

    PTE flags  = 0x1101   (bit0 V=1, bit8 KRE=1, bit12 KWE=1)
    PFN        = base_pfn = 0x2DE   (for base = 0x5bc000)
    PTE.raw    = (base_pfn << 32) | 0x1101 = 0x000002DE00001101

That quadword is what a CORRECT ITB fill for 0x20000000 must install.  The
composed PA is (0x2DE << 13) | 0 = 0x5BC000 -- the loaded image.  The console
sets VPTB = 0x200000000 and installs NO ITB entry for 0x20000000 itself; it
relies on the hardware taking a fetch-driven ITB miss and PALcode filling from
l3pt1[0].

## 4. The architected correct path vs. what we observe

Correct (per the reference):
    fetch 0x20000000 -> ITB MISS (nothing valid yet in the new context)
      -> PAL ITB-miss handler -> VA_FORM(0x20000000) via VPTB=0x200000000
      -> load l3pt1[0] = 0x000002DE00001101 -> install PFN 0x2DE
      -> retry fetch HITS -> reads the real image -> VMB runs.

Observed (JRN-VMB-001 Sec 7.6 + this session's log review):
    fetch 0x20000000 -> ITB HIT, PFN 0 -> PA 0 -> reads 0x00000000
      = CALL_PAL HALT -> halt code 0.  Miss probe fired ZERO times.

In a faithful emulation there MUST be exactly one miss at 0x20000000 and its
fill MUST yield PFN 0x2DE.  We see NO miss and a HIT with PFN 0.  That gap is
the whole bug.

## 5. Hypotheses after the reference read

  H-A (NEW, LEADING) -- a stale ITB entry survived the boot context swap.
      The console changes PTBR and reuses ASN 0, then jumps.  boot.c contains
      NO TBIA/TBIAP; the TB invalidate on the swap is PALcode's responsibility
      (swpctx-class).  If EmulatR does not invalidate the ITB when PTBR/ASN
      change at the boot handoff, a leftover console-era entry (identity-ish or
      zero, ASN 0) still MATCHES VA 0x20000000 and is HIT instead of missing.
      This explains the two facts no other hypothesis does together: (a) a HIT,
      not a miss; (b) PFN 0 rather than 0x2DE.  It fits the reference exactly --
      the console never installs a 0x20000000 ITB entry, so any entry present at
      first fetch is stale by construction.

  H-B (was H2) -- VA_FORM base stranded.  Weaker now: a stranded base corrupts a
      MISS fill, but no miss fired.  Also note a CAUTION on the STRANDED
      predicate: the reference VPTB is 0x200000000, which legitimately has ZERO
      bits in <63:43>.  The Step 1 miss-probe's STRANDED = (vptb!=0 &&
      (va_ctl & 0xFFFFF80000000000)==0) was tuned to the memtest ACV context and
      would FALSE-POSITIVE on this legitimately-low VMB VPTB.  Do not treat
      STRANDED=1 as H2-confirmed for the VMB case; the hit-path PTE is the
      reliable signal.

  | Probe output at 0x20000000        | Conclusion                              |
  |-----------------------------------|-----------------------------------------|
  | pte=...2DE...1101, pfn=2de, ZERO=0| Correct fill -- halt is elsewhere; re-check |
  | valid=1, pfn=0 (ZEROPFN=1)        | A REAL wrongly-filled entry.  Chase the HW_MTPR ITB_PTE site that installed PFN 0 for tag 0x20000000 |

Expected, per H-A: valid low or pfn=0 with an ASN-0 / stale tag -- NOT
0x000002DE00001101.
